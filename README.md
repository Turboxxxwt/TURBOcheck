# TURBO查件

一个给大学生用的极简安卓 App：把拼多多、淘宝、京东（以及菜鸟、丰巢、顺丰）的取件通知集中成一张清单。

## 能做什么

- **自动汇总取件码**：收到快递通知时自动识别并加入清单，不用翻通知栏。
- **一键身份码**：首页直达拼多多身份码、淘宝菜鸟驿站身份码、近邻宝取件，到驿站出示即可。
- **按柜号分类**：识别货架码里的柜号（`3-2-3012` → 「3号柜」）或文案中的「12号柜 / A区」，首页自动按柜号分组，取件时一眼看清去哪排。
- **多平台**：拼多多 / 淘宝 / 天猫 / 京东 / 菜鸟 / 丰巢 / 顺丰，可在设置里逐个开关。
- **短信兜底**：部分驿站仍用短信发码，可选开启。
- **手动补录**：识别不了的直接手动加。
- **一键完成**：取完件点勾选移除，误触可撤销。
- **关于APP**：设置页入口，含作者、抖音主页与反馈邮箱；系统返回键从设置/关于页一律回到主界面。
- **纯本地**：无账号、无联网、无埋点，数据只存在手机里。

## 身份码 / 取件跳转说明

首页身份码分组的三个入口，实现各不相同：

- **拼多多**：私有 scheme `pinduoduo://com.xunmeng.pinduoduo/mdkd/package` 直达扫码亮灯页。
- **淘宝菜鸟驿站**：私有 scheme + H5 直达当前账号的动态身份码页。
- **近邻宝**：优先拉起近邻宝独立 App（`com.jlb.mobile`）；未安装则拉起微信，提示在微信搜索「近邻宝」小程序。

关于近邻宝的说明：微信小程序的明文 scheme 需要完整 AppID + 已发布页面 path，而「近邻宝」小程序的 AppID 在公开渠道是脱敏的，因此**不使用来路不明的 scheme / ticket**，改为上面这种可靠的回退策略。如果你已知本校近邻宝小程序的完整 AppID 与首页 path，可自行在 `AppLinks.kt` 增加明文 scheme 常量。

这些都是平台私有机制，不是官方 API，可能随 App 版本更新失效，集中定义在 `core/AppLinks.kt`，失效时改对应常量即可。身份码本身由各平台账号实时生成，本 App 不存储、不展示其内容。

## 柜号分类说明

取件码按柜号分组展示，识别规则在 `CodeParser.extractCabinet()`：

- 货架码 `3-2-3012` → 首段作为柜号「3号柜」。
- 文案中的「12号柜」「A区」「柜号：A3」直接提取。
- 识别不到的归入「其他」，排在最后。

没有柜号不影响取件码本身的识别；柜号只是帮助你到驿站后快速定位。

## 不能做什么（重要）

拼多多、淘宝、京东**都没有开放取件码接口**。任何声称"直接读取某 App 数据"的做法，本质都是逆向私有 API 或无障碍模拟点击，既不稳定也可能违规。

本 App 走的是 Android 官方的 `NotificationListenerService`：

- 只能读**用户主动授权后、系统推送出来的通知**。
- 不反编译、不模拟点击、不读取 App 私有数据、不上传任何内容。
- 不拦截、不修改、不删除你的任何通知。

**身份码**（驿站 App 里那个动态二维码）由 App 实时生成，通知里不会出现，因此无法自动读取。如果你的校园驿站用的是固定数字身份码，可以在首页手动添加并勾选「身份码」。

## 编译运行

1. 用 Android Studio（Ladybug 或更新版本）打开本目录。
2. 首次打开会自动下载 Gradle 和依赖，等它跑完。
3. 连接手机（打开开发者选项 + USB 调试），点运行。

要求：Android 8.0（API 26）及以上，compileSdk 35。

命令行也可以（已附带 wrapper，无需预装 Gradle）：

```bash
./gradlew assembleDebug
# 产物在 app/build/outputs/apk/debug/app-debug.apk
./gradlew test   # 跑解析器测试
```

## 首次使用

1. 打开 App，首页顶部会出现「开启通知读取」——点进去，在系统设置里允许本 App 读取通知。
2. 设置页里确认需要监听的平台都已打开。
3. 之后收到取件通知，号码会自动出现在首页。

如果某家 App 的通知内容被厂商系统折叠或加密（少数定制 ROM 会这样），解析可能失败，用手动补录即可。

## 目录结构

```
app/src/main/java/com/student/qujian/
├── MainActivity.kt                      # 页面切换
├── model/Pickup.kt                      # 数据模型
├── core/CodeParser.kt                   # 取件码解析规则（核心）
├── core/PickupStore.kt                  # 本地存储 + 去重
├── core/NotificationHelper.kt           # 权限检查与跳转
├── service/PickupNotificationListener.kt# 通知监听
├── service/SmsReceiver.kt               # 短信兜底
└── ui/                                  # Compose 界面
```

解析规则集中在 `CodeParser.kt`，每家平台的文案格式都不一样。如果发现某种通知识别不了，把通知原文加成一个测试用例扔给 `CodeParserTest`，加一条规则就行，不用动别的代码。

## 隐私

- 不申请网络权限（`android.permission.INTERNET` 根本没声明）。
- 数据存在 `SharedPreferences` 里，只在本机。
- 短信权限默认关闭，开了也只解析取件码。
